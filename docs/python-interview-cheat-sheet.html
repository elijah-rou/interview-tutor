    Interview prep · Python 3.11+

    Python interview cheat sheet

    This reference targets Python 3.11 or newer. It favors the standard library and patterns that are easy to explain under interview pressure.

    Choose the right structure

    Need Python structure Important operations
    LIFO stack list append / pop: amortized O(1)
    FIFO queue collections.deque append / popleft: O(1)
    Double-ended queue collections.deque append/pop at either end: O(1)
    Smallest item or priority queue heapq over a list peek: O(1), push/pop: O(log n)
    Membership or deduplication set average O(1) lookup/add/remove
    Key to value/node dict average O(1) lookup/insert/delete
    Sorted search over a list bisect search: O(log n), insertion: O(n)

    Do not use list.pop(0) as a queue: shifting the remaining elements costs O(n).

    Heaps and priority queues

    heapq is a min-heap. The smallest item is always at index 0; the rest of the list is heap-ordered, not fully sorted.

    import heapq

heap = [7, 2, 5]
heapq.heapify(heap)          # O(n), heap is now [2, 7, 5] or equivalent
heapq.heappush(heap, 3)     # O(log n)
smallest = heap[0]          # O(1), does not remove
smallest = heapq.heappop(heap)  # O(log n)

    Useful combined operations:

    removed = heapq.heappushpop(heap, item)  # push, then remove the smallest
removed = heapq.heapreplace(heap, item)  # remove the smallest, then push

    heappushpop may return item without changing the existing heap. heapreplace always removes an existing item and requires a non-empty heap.

    Max-heap pattern

    For a max-heap on Python 3.11+, negate numeric priorities:

    max_heap: list[int] = []
heapq.heappush(max_heap, -value)
largest = -heapq.heappop(max_heap)

    For (priority, value) entries, negate only the priority.

    Stable priorities and incomparable payloads

    Tuples compare from left to right. If two priorities tie, Python tries to compare the payloads and may raise TypeError. Add a unique sequence number as the tie-breaker:

    from itertools import count
from typing import Any

sequence = count()
priority_queue: list[tuple[int, int, Any]] = []

heapq.heappush(priority_queue, (priority, next(sequence), item))
priority, _, item = heapq.heappop(priority_queue)

    Negate priority as well when a larger number means higher priority.

    Keep the k largest values

    Keep a min-heap containing only the best k values. Its root is the current cutoff:

    def k_largest(values: list[int], k: int) -> list[int]:
    if k <= 0:
        return []

    heap: list[int] = []
    for value in values:
        if len(heap) < k:
            heapq.heappush(heap, value)
        elif value > heap[0]:
            heapq.heapreplace(heap, value)

    return sorted(heap, reverse=True)

    Time is O(n log k); extra space is O(k). To keep the k smallest values, maintain a size-k max-heap using negated values.

    Stacks, queues, and monotonic structures

    Stack and queue

    from collections import deque

stack: list[int] = []
stack.append(10)
top = stack[-1]
value = stack.pop()

queue: deque[int] = deque()
queue.append(10)
front = queue[0]
value = queue.popleft()

    Monotonic stack: next greater value

    Store indices when answers depend on position. This stack keeps unresolved values in decreasing order:

    def next_greater_values(numbers: list[int]) -> list[int]:
    answers = [-1] * len(numbers)
    stack: list[int] = []

    for index, value in enumerate(numbers):
        while stack and numbers[stack[-1]] < value:
            answers[stack.pop()] = value
        stack.append(index)

    return answers

    Each index enters and leaves the stack once, so total time is O(n), not O(n²).

    Monotonic deque: sliding-window maximum

    The deque stores useful indices in decreasing value order:

    from collections import deque


def sliding_maximum(numbers: list[int], window_size: int) -> list[int]:
    if not 1 <= window_size <= len(numbers):
        return []

    candidates: deque[int] = deque()
    maxima: list[int] = []

    for index, value in enumerate(numbers):
        while candidates and candidates[0] <= index - window_size:
            candidates.popleft()
        while candidates and numbers[candidates[-1]] <= value:
            candidates.pop()
        candidates.append(index)

        if index >= window_size - 1:
            maxima.append(numbers[candidates[0]])

    return maxima

    This template treats a non-positive or oversized window as invalid and returns an empty list.

    Graph representations and traversal

    Choose a representation based on the operations the problem needs:

    # Unweighted directed graph with nodes 0..n-1.
directed: list[list[int]] = [[] for _ in range(node_count)]
for source, destination in edges:
    directed[source].append(destination)

# Undirected graph: add each edge in both directions.
undirected: list[list[int]] = [[] for _ in range(node_count)]
for source, destination in edges:
    undirected[source].append(destination)
    undirected[destination].append(source)

# Weighted graph: each input edge is (source, destination, weight).
weighted: list[list[tuple[int, int]]] = [[] for _ in range(node_count)]
for source, destination, weight in weighted_edges:
    weighted[source].append((destination, weight))

    Use set neighbors when deduplication or edge removal matters. Use dict[node, list[node]] when node IDs are sparse or not integers. defaultdict(list) is concise, but reading a missing key also inserts it.

    Breadth-first search

    BFS finds shortest path lengths in an unweighted graph. Mark a node seen when enqueuing it, not when dequeuing it, to avoid duplicate queue entries.

    from collections import deque


def shortest_hops(graph: list[list[int]], start: int) -> list[int]:
    distances = [-1] * len(graph)
    distances[start] = 0
    queue = deque([start])

    while queue:
        node = queue.popleft()
        for neighbor in graph[node]:
            if distances[neighbor] != -1:
                continue
            distances[neighbor] = distances[node] + 1
            queue.append(neighbor)

    return distances

    Iterative depth-first search

    def reachable_nodes(graph: list[list[int]], start: int) -> set[int]:
    seen = {start}
    stack = [start]

    while stack:
        node = stack.pop()
        for neighbor in graph[node]:
            if neighbor in seen:
                continue
            seen.add(neighbor)
            stack.append(neighbor)

    return seen

    Iterative DFS avoids Python's shallow recursion limit. To visit every component, start a new traversal from each node not already seen.

    Topological sort with Kahn's algorithm

    An order containing fewer than node_count nodes means the directed graph has a cycle.

    from collections import deque


def topological_order(graph: list[list[int]]) -> list[int]:
    indegree = [0] * len(graph)
    for neighbors in graph:
        for neighbor in neighbors:
            indegree[neighbor] += 1

    ready = deque(
        node for node, degree in enumerate(indegree) if degree == 0
    )
    order: list[int] = []

    while ready:
        node = ready.popleft()
        order.append(node)
        for neighbor in graph[node]:
            indegree[neighbor] -= 1
            if indegree[neighbor] == 0:
                ready.append(neighbor)

    return order if len(order) == len(graph) else []

    Dijkstra's algorithm

    Use Dijkstra only when edge weights are non-negative. heapq has no decrease-key operation, so push the improved distance and skip stale entries later.

    import heapq
from itertools import count


def shortest_weighted_paths(
    graph: dict[str, list[tuple[str, int]]], start: str
) -> dict[str, int]:
    sequence = count()
    distances = {start: 0}
    heap = [(0, next(sequence), start)]

    while heap:
        distance, _, node = heapq.heappop(heap)
        if distance != distances[node]:
            continue

        for neighbor, weight in graph.get(node, []):
            assert weight >= 0
            candidate = distance + weight
            if candidate >= distances.get(neighbor, float("inf")):
                continue
            distances[neighbor] = candidate
            heapq.heappush(
                heap, (candidate, next(sequence), neighbor)
            )

    return distances

    Doubly linked lists

    A doubly linked list is useful when a dictionary locates nodes and the algorithm must unlink or move any node in O(1), as in an LRU cache. Dummy head and tail sentinels remove most empty-list and endpoint branches.

    from __future__ import annotations

from dataclasses import dataclass


@dataclass(eq=False, slots=True)
class Node:
    key: int | None = None
    value: int | None = None
    previous: Node | None = None
    next: Node | None = None


class DoublyLinkedList:
    def __init__(self) -> None:
        self.head = Node()
        self.tail = Node()
        self.head.next = self.tail
        self.tail.previous = self.head

    def add_first(self, node: Node) -> None:
        assert node.previous is None
        assert node.next is None
        first = self.head.next
        assert first is not None

        node.previous = self.head
        node.next = first
        self.head.next = node
        first.previous = node

    def remove(self, node: Node) -> None:
        previous = node.previous
        following = node.next
        assert previous is not None
        assert following is not None

        previous.next = following
        following.previous = previous
        node.previous = None
        node.next = None

    def remove_last(self) -> Node | None:
        last = self.tail.previous
        assert last is not None
        if last is self.head:
            return None
        self.remove(last)
        return last

    LRU operations then become:

    • hit: dictionary lookup, remove(node), then add_first(node)
    • insert: add to the dictionary and front of the list
    • eviction: remove_last(), then delete that node's key from the dictionary

    In application code, collections.OrderedDict already provides move_to_end and popitem(last=False). Interviews may still ask for the explicit dictionary plus linked-list implementation.

    asyncio essentials

    asyncio provides cooperative concurrency, primarily for waiting on network, subprocess, timer, or other asynchronous I/O. It does not make CPU-bound Python execute in parallel.

    • Calling an async def function creates a coroutine object; it does not run it.
    • await suspends only the current task and lets another ready task run.
    • asyncio.create_task schedules a coroutine concurrently on the current event loop.
    • Code between await points runs without another task on that event-loop thread taking over.
    • Shared state can still race when a read-modify-write operation spans an await.

    Entry point and sequential awaits

    import asyncio


async def main() -> None:
    first = await fetch_one("/first")
    second = await fetch_one("/second")  # starts after first completes
    print(first, second)


if __name__ == "__main__":
    asyncio.run(main())

    Use one asyncio.run at the synchronous program boundary. In an already asynchronous framework, await main() instead of starting a nested event loop.

    Structured concurrency with TaskGroup

    A task group waits for all child tasks. If one fails, it cancels the unfinished siblings and eventually raises an ExceptionGroup.

    import asyncio


async def load_pair() -> tuple[bytes, bytes]:
    async with asyncio.TaskGroup() as group:
        first_task = group.create_task(fetch_one("/first"))
        second_task = group.create_task(fetch_one("/second"))

    return first_task.result(), second_task.result()

    Prefer TaskGroup when the child operations form one unit of work. Keep task references when their results are needed.

    gather, completion order, and timeouts

    # Results preserve the input order, not completion order.
results = await asyncio.gather(*(fetch_one(url) for url in urls))

# Consume results in completion order.
for completed in asyncio.as_completed(
    [fetch_one(url) for url in urls]
):
    result = await completed

# Bound one operation or block. Raises TimeoutError on expiry.
async with asyncio.timeout(2.0):
    result = await fetch_one(url)

    Unlike TaskGroup, default gather propagation of one exception does not automatically cancel other already-scheduled awaitables. Choose deliberately rather than treating the two APIs as interchangeable.

    Bound concurrent work

    A semaphore bounds active operations, though the following still creates one task per URL and is therefore appropriate only for a bounded input collection:

    import asyncio


async def fetch_all(urls: list[str]) -> list[bytes]:
    semaphore = asyncio.Semaphore(20)

    async def fetch_bounded(url: str) -> bytes:
        async with semaphore:
            return await fetch_one(url)

    async with asyncio.TaskGroup() as group:
        tasks = [group.create_task(fetch_bounded(url)) for url in urls]

    return [task.result() for task in tasks]

    For a large or streaming input, use a fixed worker pool and a bounded queue so both active operations and buffered work stay bounded:

    import asyncio
from collections.abc import Iterable

STOP = object()


async def worker(queue: asyncio.Queue[object]) -> None:
    while True:
        item = await queue.get()
        try:
            if item is STOP:
                return
            await process(item)
        finally:
            queue.task_done()


async def process_all(items: Iterable[object]) -> None:
    worker_count = 20
    queue: asyncio.Queue[object] = asyncio.Queue(maxsize=100)

    async with asyncio.TaskGroup() as group:
        for _ in range(worker_count):
            group.create_task(worker(queue))

        for item in items:
            await queue.put(item)
        await queue.join()

        for _ in range(worker_count):
            await queue.put(STOP)

    queue.task_done() belongs in finally; otherwise an exception or early return can leave queue.join() blocked forever.

    Cancellation and cleanup

    Cancellation is normal control flow in async programs. Use async context managers for resources, put cleanup in finally, and do not swallow CancelledError:

    import asyncio


async def consume(connection: Connection) -> None:
    try:
        async with connection:
            while message := await connection.receive():
                await handle(message)
    except asyncio.CancelledError:
        raise
    finally:
        record_disconnect()

    A broad except BaseException catches cancellation. A normal except Exception does not catch asyncio.CancelledError on supported Python versions.

    Locks and blocking code

    Protect state transitions that span an await:

    lock = asyncio.Lock()

async with lock:
    current = balances[account_id]
    updated = await validate_update(current, change)
    balances[account_id] = updated

    Keep critical sections small. Do not hold a lock while awaiting unrelated slow I/O.

    Move a blocking I/O call off the event-loop thread:

    contents = await asyncio.to_thread(path.read_bytes)

    to_thread is mainly for blocking I/O. Use a process pool or native code that releases the GIL for CPU-bound parallel work.

    Async failure checklist

    When async code hangs or behaves sequentially, check these first:

    1. A blocking call such as time.sleep, synchronous HTTP, or ordinary file I/O is running on the event-loop thread.
    2. Coroutines are created but never awaited or scheduled.
    3. Independent operations are awaited one at a time instead of placed in a TaskGroup.
    4. A queue consumer forgot task_done, or shutdown sent too few sentinels.
    5. A lock is held across slow or re-entrant work.
    6. Cancellation is caught and suppressed.
    7. Tasks are created without a bound, retained reference, or observed result.

    Use await asyncio.sleep(delay), not time.sleep(delay), inside async code.
